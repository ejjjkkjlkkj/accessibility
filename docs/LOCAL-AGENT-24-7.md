# Local Ollama coding loop (prototype)

**Status:** local developer tool; not installed or running automatically. The code-generation cycle is not proven until it has been run on a configured workstation.

## Behavior and safeguards

- Uses a local Ollama endpoint only. The endpoint must be an HTTP URL whose host is a literal loopback IP address; remote hosts, proxies, redirects, credentials, paths and query strings are rejected.
- Requires a clean Git checkout on a dedicated feature branch and refuses to run on `main` or `master`.
- Uses bounded context and patch sizes, protects the agent files and all `.github/` paths, rejects path traversal and symlinks, and validates patch paths from both Git headers and file headers.
- Runs Python tests and every discovered Cargo manifest, plus detected native-language checks. A missing required toolchain or build manifest blocks the iteration; tests are not represented as a security sandbox.
- Creates local commits only after checks pass. Pushes are disabled by default; when explicitly enabled, they are restricted to the current non-protected branch. The agent never merges or creates releases.
- Does not flash firmware, modify NVRAM or partitions, reboot the PC, or run commands generated by the model.

## Run a single iteration

Requirements: Python 3.11+, Git, Cargo/Rust, the preinstalled `x86_64-unknown-uefi` Rust target, a local Ollama installation, and the configured model already installed. The runner does not download toolchains automatically. Use a disposable checkout under a low-privilege account, without secrets or personal files. Do not run generated tests with access to sensitive data.

From PowerShell at the repository root, on a clean feature branch:

```powershell
$env:AGENT_WORKSPACE = (Get-Location).Path
$env:OLLAMA_URL = 'http://127.0.0.1:11434'
$env:OLLAMA_MODEL = 'qwen3-coder:30b'
$env:AGENT_AUTO_PUSH = '0'
$env:AGENT_MAX_RUNS = '1'
$env:AGENT_SLEEP_SECONDS = '60'
python .\tools\local_agent_loop.py
```

The first iteration still validates all available Rust manifests and Python tests. Review the resulting commit, JSONL log under `%USERPROFILE%\.local-coding-agents\`, and CI evidence before using the patch elsewhere.

## Optional per-user logon task

After manually reviewing this script and deciding to allow the service to run at logon, register the per-user scheduled task:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\install_agent_task.ps1
Start-ScheduledTask -TaskName ('LocalCodingAgent-' + (Split-Path (Get-Location).Path -Leaf))
```

This action is **not** performed by the repository change. A scheduled task does not guarantee 24/7 uptime: the PC must be awake, signed in, and Ollama available. The service can create local commits over time, so use a dedicated checkout and regularly review output.

## Evidence boundaries

- Unit tests and hosted CI validate only the code paths and commands they execute.
- The prototype has not been installed or started on the user's PC by this repository change.
- Local model use does not prove the model's correctness, that every patch is safe, or that physical UEFI boot, accessibility APIs, keyboard navigation or real audio work.
- The existing repository-owned hosted-agent workflow remains separate; this local Ollama prototype does not satisfy the hosted 24/7 coding-agent blocker.
