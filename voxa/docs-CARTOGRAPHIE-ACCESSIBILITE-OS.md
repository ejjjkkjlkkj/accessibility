# Cartographie de l'accessibilité sans vision : Windows 11, macOS, Linux, ChromeOS, et où Voxa peut réellement faire mieux
Date : 2026-10-11. Méthode : recherches web ciblées (liens ci-dessous), lecture seule de l'ISO Windows 11 fournie, état réel du dépôt Voxa. **Rien n'a été mesuré sur ces systèmes** (pas de campagne de tests avec utilisateurs) ; les affirmations sont marquées SOURCÉ (lien), CONNU (connaissance générale non revérifiée ici) ou NON VÉRIFIÉ. Les sources sont souvent anecdotiques ou datées : à relire avant de s'y fier.

## 2. Ce que Voxa peut faire mieux, sans mensonge
Chaque point est un *objectif mesurable* ; le statut dit où l'on en est.
| # | Avantage visé | Pourquoi les autres sont limités | Mesure proposée | Statut |
|---|---|---|---|---|
| A1 | Parole française **dès l'allumage, sans combinaison de touches ni installation** | Windows : activation par raccourci ; firmware : muet | Temps entre l'affichage du chargeur et la première annonce, sans touche | émulation : oui ; matériel : NOT_VALIDATED |
| A2 | Un seul composant : lecteur **intégré** au système, aucun lecteur tiers | Windows/Linux dépendent d'un lecteur et d'une API séparés | architecture : cœur unique + contrat sémantique obligatoire pour les applications natives | PARTIAL (une application) |
| A3 | **Hors ligne par construction** | voix naturelles Windows nécessitent des téléchargements (CONNU) | zéro dépendance réseau dans le chemin vocal | PASS (par conception ; vérifié par absence de pile réseau) |
| A4 | Chaîne de secours **explicite** : parole → bips codés → (prévu) braille/série | les échecs de pile audio sont souvent silencieux | test d'injection de pannes (audio absent, tampon trop long) | PASS en émulation |
| A5 | Actions sensibles **toujours confirmées** et annulables | dépend de chaque application | tests de confirmation/annulation | PASS en émulation |
| A6 | Journal d'annonces testable (le contenu parlé est vérifiable) | peu d'outils de test de lecteurs d'écran | PCM transmis comparé à une référence | PASS en émulation |
| A7 | Récupération et diagnostic accessibles (clé de démarrage) | firmware/BIOS muets | scénarios « sans écran » avec utilisateurs aveugles | NOT_VALIDATED |

## 3. Ce où Voxa est (et restera longtemps) en retard
Qualité et naturel de la voix ; braille ; web et applications (formulaires, tableaux, documents) ; langues ; compatibilité matérielle ; écosystème d'applications ; noyau, pilotes, système de fichiers, réseau (Voxa OS n'existe pas). **Un système « complet comme Windows » représente des années-hommes** : il n'est pas atteignable par une série de sessions de développement, et le dire est nécessaire.

## 4. Priorités qui découlent de la cartographie (ordre)
1. **Preuve sur machine réelle** (une clé vide, essai du démarrage et de la parole) : sans elle A1 reste théorique.
2. **Évaluation humaine de la voix** (intelligibilité) avant tout autre investissement vocal ; mesure de latence de première annonce.
3. **Contrat sémantique + application de fichiers** : lecture/navigation de dossiers (c'est la tâche quotidienne n° 1 qu'un lecteur doit couvrir) ; nécessite FAT/NVMe en lecture seule.
4. **Braille HID** (HUTRR78) : l'USB-IF a publié la page d'usage ; le support logiciel est encore rare — niche où Voxa peut arriver tôt, mais **sans afficheur braille il est impossible de valider**.
5. **Noyau minimal** (carte mémoire, allocateur, tâches), puis pilotes clavier/stockage.
6. **Comparaison mesurée avec Windows (Narrator), macOS (VoiceOver), Linux (Orca/Fenrir), ChromeOS (ChromeVox)** sur 5 tâches standard avec des utilisateurs de lecteurs d'écran : c'est la seule façon de justifier « mieux ».

## 4 bis. Images et documents récupérés
